# UniBridge — стартова версія

Python 3.11+. Проєкт за прикріпленим ТЗ. Це стартова реалізація, а не повне виконання всіх вимог.

## Запуск у Windows

1. Розпакуй архів, відкрий папку unibridge у VS Code.
2. У терміналі:

```powershell
py -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
Copy-Item .env.example .env
```

3. Створи бота через @BotFather командою /newbot. Встав отриманий токен у BOT_TOKEN у файлі .env.
4. Вкажи свій числовий Telegram ID у ADMIN_IDS. Це не номер телефону і не @username. Можна вказати кілька ID через кому.
5. Запусти:

```powershell
.venv\Scripts\python bot.py
```

6. Натисни /start у Telegram. Адміністратор отримає меню перевірки. Для тесту школяра та студента потрібні інші Telegram-акаунти.

Токен не надсилай у чат і не завантажуй .env у GitHub. /id у боті показує ID користувача після запуску.

## Реалізовано

- Школяр / студент, ім’я студента і вибір кількох категорій.
- Запитання 20–1000, відповіді 20–3000 символів.
- Модерація запитань і відповідей, схвалення, відхилення, уточнення з коментарем.
- Випадкове призначення до трьох студентів категорії, пропуск.
- До трьох схвалених відповідей; перевірка призначення і власника виправлення.
- Повторна розсилка іншим студентам через 24 години без відповіді на перевірці чи схваленої відповіді.
- Завершення без відповіді через п’ять днів; відповіді на перевірці затримують закриття.
- SQLite, збереження стану введення і черги вихідних повідомлень; повтори після мережевих помилок.
- Антиспам: 60 секунд між новими запитаннями та перевірка однакових текстів автора.
- Адміністратор за списком Telegram ID, призначення модераторів, блокування.
- Тексти передаються новими повідомленнями без пересилання контактів автора.

## Адміністративні команди

/mod ID — призначити модератора.
/unmod ID — зняти права, скинути роль; користувач знову обирає роль через /start.
/block ID, /unblock ID — доступ користувача.

Користувач має спершу натиснути /start. Адміністратора не можна блокувати чи змінити командою.
/cancel скасовує введення, не видаляє вже надісланий матеріал.

## Ще не реалізовано з повного ТЗ

- Редактор категорій, правил, лімітів і таймерів у меню адміністратора.
- Детальна статистика за ролями й статусами, сторінки всіх користувачів, журнал дій у меню.
- Окремий перегляд статусів усіх запитань і скарги модераторів.
- Дослівні повідомлення з усього додатка А та всі проміжні статуси із ТЗ.
- Автоматичне видалення даних: поки звернення до адміністратора.
- Сповіщення авторам зайвих відповідей, коли третю відповідь уже схвалено.

Статистика наразі показує загальні числа; список користувачів — останні 50. Категорії та правила змінюються в texts.py. Таймери в services/delivery.py: доба на повторну розсилку, п’ять днів очікування. Після першої схваленої відповіді запитання залишається доступним призначеним студентам до трьох відповідей.

## Перевірка

```powershell
.venv\Scripts\python -m unittest -v
```

Автотести перевіряють межу у три схвалення, повторне схвалення, закрите запитання та збереження черги після повторного відкриття БД. Живі Telegram-сценарії потребують токена і тестових акаунтів; у середовищі створення не перевірені.

## Розгортання

Потрібен один постійний процес `python bot.py` і постійний диск для DATABASE_PATH. Не запускай два екземпляри для одного токена/БД. Не використовуй webhook одночасно з polling. Щоб зупинити локально — Ctrl+C.

Черга має доставку щонайменше один раз: збій між надсиланням і записом результату може спричинити повторне повідомлення. Постійно недоступним адресатам повтори тривають; адміністратор поки перевіряє це через БД. Telegram не гарантує доставку користувачам, які заблокували бота. Роби резервну копію SQLite через backup API або копіюй файл після зупинки процесу.


## Структура коду

| Файл | Призначення |
| --- | --- |
| bot.py | Точка запуску |
| config.py | Зчитування .env і перевірка конфігурації |
| app.py | Збирання застосунку, реєстрація обробників, цикл отримання оновлень |
| database.py | SQLite, таблиці, запити й обмеження схвалення відповідей |
| texts.py | Категорії та правила |
| keyboards.py | Клавіатури й меню |
| handlers/messages.py | Текстові повідомлення, команди адміністратора та введення даних |
| handlers/callbacks.py | Натискання inline-кнопок, перевірка ролей і доступу |
| services/submissions.py | Валідація та збереження запитань, відповідей, виправлень |
| services/moderation.py | Формування матеріалів для модераторів |
| services/distribution.py | Випадковий вибір студентів і призначення запитань |
| services/delivery.py | Черга повідомлень, повтори надсилання, терміни очікування |
| test_store.py | Перевірки бази даних і ліміту відповідей |

Application поєднує модулі обробників і сервісів. Вони використовують спільні self.bot, self.store і self.admins. Обробка послідовна: з’єднання SQLite не передається в інші потоки.

Рефакторинг не змінює схему БД. Для оновлення з попередньої версії зупини бот, збережи .env та unibridge.db і перенеси їх у папку нової версії. Команда запуску лишається python bot.py. Функції, яких бракує до повного ТЗ, залишаються в переліку вище.
